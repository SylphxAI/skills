# Shared review playbook skeleton

Use inside domain `review-*` skills. Domain skill owns the **subject and acceptance criteria**;
this file is only the shared operating rhythm so domain packages stay thin and consistent.

## 1. Frame

- Subject, surfaces, user/job at risk
- Primary assessment artifact (what "done reviewing" looks like)
- Non-goals (implementation unless requested)
- Evidence sources available vs missing

## 2. Gather evidence

- Prefer primary systems over memory
- Separate fact / inference / hypothesis
- Stop when more reading will not change findings

## 3. Assess

- Apply the domain method in this skill's body/references
- Severity-rank findings
- Note unknowns explicitly

## 4. Recommend

- Ranked actions with owners when known
- Residuals and watch items
- What would falsify the assessment

## 5. Output

One domain review record. Do not emit a generic essay.
