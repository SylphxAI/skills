# Product Finisher

Remove **material burrs** so an integrated product feels intentional and release-grade.
Improve the active product/workspace by raising **coherence, states, feel, and obvious quality gaps**—not by adding new product bets.

**Primary class:** `workflow`. One **cycle** only.  
For deep finish doctrine, also use `product-finish` when the pass is large.

## When to use

- Integrated product exists; rough edges, inconsistent states, weak hierarchy, incomplete content
- Pre-demo / pre-release polish with a bar

## When not to use

- Idea still unproven → `product-prototyper`
- Missing capability → `product-builder`
- Outage/regression harm → `product-maintainer` first
- Scale strategy → `product-expander`

## Methodology

Finish pass: **traverse reality → gap list above threshold → fix → recapture**.  
Depth is semantic resolution, not ornament count. Micro-thrash below user-visible delta is out.

## One cycle

### 1. Frame
- Bind exact **subject** (repo, build, URL, platform, locale).
- Declare **finish target** for this cycle: e.g. demo-ready · candidate · release-finish.
- Non-goals: new features, architecture rewrites, infinite pixel hunting.

### 2. Research / inspect
- Actually run or render the product.
- Walk happy path plus empty/error/loading/small/wide/locale as applicable.
- Note gaps that hurt comprehension, trust, accessibility, feedback, or identity.
- Optional: short competitive finish bar—only if it changes the gap list.

### 3. Admit work for this cycle
- **In:** all capacity-feasible gaps **above** a user-visible / bar-visible threshold.
- **Out:** microscopic tweaks with no observable delta; net-new product scope.
- Many small fixes OK if they serve one finish target.

### 4. Implement
- Fix in product (and engine only when the burr is truly a shared floor).
- Prefer consistency with existing design language over inventing a new one mid-pass.
- Remove placeholders when target fidelity requires real content.

### 5. Deliver / verify
- Recapture the same journeys; before/after evidence when useful.
- Confirm finish target for this cycle is met or list only below-threshold leftovers.
- Do not claim release authority if process requires a human/ship gate.

## Cycle done when

1. Subject was really inspected, not only described.
2. Above-threshold gaps admitted for this cycle are fixed or externally blocked.
3. Recapture matches the framed finish target or honest residual list.
4. No feature-scope smuggling.

## Output (short)

- Target · inspected surfaces · fixes · recapture evidence · leftovers
