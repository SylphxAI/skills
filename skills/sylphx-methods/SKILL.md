# Sylphx Methods

This package is the **installed company method library** for Sylphx agents.
It is not a vague "service consult" layer and not optional trivia.

Sylphx products and agents **are** these methods: agent-native delivery, evidence
honesty, Keel titles, Platform-first, product cycles, design, and domain reviews.
Specialized task skills (`build-keel-title`, asset producers, etc.) cover hot
paths; **this package holds the rest of the researched operating knowledge**.

## Open this when

- Doing work for Sylphx, Keel, Platform, Cubeage, or other company repos
- You need org standards (delivery, agent-native, source authoring, engineering, …)
- You need a product-cycle method (prototype/build/maintain/expand/finish/pursue/betterment)
- You need a design blueprint or domain review playbook
- A dedicated task skill is too narrow or missing for the job

## Do not treat as

- An extra abstraction above "real work" — the folders **are** the work methods
- Something only for "policy people" — agents execute these methods
- A replacement for Keel/Platform live tools — methods + live proof together

## Workflow (minimal nesting)

1. Open **[references/INDEX.md](references/INDEX.md)** — **job → path** map (not a maze).
2. Open **one** folder `README.md` for the job.
3. Open nested files only if that README points to them.
4. Apply in the **active product repo** with real evidence.
5. In your report, cite the exact path you used (so the method stays visible).

## Hot paths already have task skills

Prefer these when they match exactly:

| Job | Task skill |
| --- | --- |
| Keel title/app | `build-keel-title` |
| UI craft | `craft-product-interface` |
| 2D sprites/maps/assets | `produce-game-2d-*` / `produce-product-assets` |
| Local preview proof | `verify-local-web-preview` |
| Incidents | `run-incident-response` |
| Versions | `select-dependency-versions` |
| Author a skill | `author-skill` |

Still open **this** library when those jobs need org standards (delivery, agent-native, source authoring, Platform-first, …).
