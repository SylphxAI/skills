# Consult Sylphx Methods

This skill is a **library**, not a single procedure. It preserves migrated org methods after the industry clean-break without putting 100+ packages into the skill listing.

## When to use

- A task needs Sylphx standards, review playbooks, or product/design methods
- No dedicated task skill covers the job
- You need progressive depth (checklists, schemas, references) for a domain

## Workflow

1. Open [references/INDEX.md](references/INDEX.md).
2. Pick the row that matches the job (standards / reviews / design / methods).
3. Read that folder's `README.md` first.
4. Open nested `references/` files only when the README says they apply.
5. Apply the method to the **current product repo** and its live evidence.
6. Do not re-publish these folders as new installable skills unless they pass the task-skill test in `docs/MODEL.md`.

## Relationship to task skills

Prefer a dedicated task skill when one exists (`author-skill`, `build-keel-title`, `craft-product-interface`, asset producers, incident response, etc.). Use this library for breadth that must not bloat the catalog listing.

## Output

Cite which knowledge path you used, what you applied, and residuals.
