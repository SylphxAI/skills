# Review Privacy and Data Rights

Shared rhythm: [review-playbook-skeleton.md](references/review-playbook-skeleton.md).

When the primary outcome is an **assessment of privacy + data-rights posture**, run one review.

## Scope

Covers both:

1. Privacy data lifecycle (collection, purpose limits, retention, deletion)
2. Data-rights operations (access, export, deletion, audit trails)

These were separate listings but share one acceptance outcome: a privacy/rights **review record** with residuals. Load domain depth only as needed.

## Method

1. Frame surfaces, data classes, legal bases, and request types in scope.
2. Read [privacy lifecycle method](references/privacy-lifecycle/METHOD.md) for lifecycle controls.
3. Read [data-rights operations method](references/data-rights-operations/METHOD.md) for DSAR/export/delete ops.
4. Open nested `references/` under those folders only for schemas/checklists required by the case.
5. Produce one assessment: findings, severity, evidence gaps, ranked actions.
6. Do not implement product fixes unless the user expanded scope to remediation.

## Output

Privacy & data-rights review record · residuals · recommended actions
