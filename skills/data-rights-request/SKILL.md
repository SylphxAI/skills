# Data Rights Request

One request ID through receive, acknowledge, identity and authority check, scope, plan, fulfill, reconcile, deliver, and close. Duplicate requests, missing information, holds, delivery failures, partial fulfillment, scope disputes, and reopened cases keep the same request ID and a clear customer status. Record the authority that controls each deadline. A download link without reconciliation is not fulfillment.

Open [request control and fulfillment](references/request-control-and-fulfillment.md) for identity, authorization, per-system fulfillment, and export quality. Open [edge cases and proof](references/rights-edge-cases-and-proof.md) for holds, shared workspaces, backups, and deletion invariants.

Use `privacy-lifecycle` to design the control system rather than fulfill one request.
