# Run Product Feedback Loop

Turn source-preserving user signals into validated product action and close the
loop with the affected people.

## Method

1. Record the product scope, feedback sources, audiences, entry contexts,
   privacy and retention needs, and the owners for product, support, safety,
   security, and external-platform responses.
2. Provide accessible private intake with optional free text, minimal context,
   attachment preview, consent, contact preference, acknowledgement, retry,
   deduplication, retention, access, and deletion behavior.
3. Preserve each signal's source, locale, product release, context, original
   wording, consent, identity confidence, selection bias, and correction state.
4. Cluster signals by the underlying user problem and affected state. Keep
   contradictory reports and minority cohorts visible.
5. Route urgent support, safety, security, privacy, payment, entitlement,
   accessibility, refund, crash, and data-loss signals directly to their owners.
6. Link each material cluster to prevalence denominators, severity, mechanism
   hypotheses, contrary evidence, an owner, a proposed action, and an independent
   way to evaluate the result.
7. Respond through the current authorized channel using verified, privacy-safe
   facts. Close private loops with the current received, investigating, shipped,
   policy-limited, or support-resolved state owned by the product.
8. Re-read the changed product path after release and update the cluster with
   the observed outcome and durable decision.

Read [feedback learning](references/feedback-learning-loop.md) when the task
needs deeper intake, clustering, routing, or measurement guidance. Open
[review solicitation policy](references/review-solicitation-policy/METHOD.md)
when the request asks when or how to invite a public store or platform review.

## Output

Return the scoped sources, normalized clusters, urgent routes, product actions,
owners, customer responses, and observed outcomes.
