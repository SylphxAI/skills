# Review solicitation policy

Define when a product may present a native public-review request while keeping
eligibility neutral, voluntary, and independent of product benefits.

Retrieve current first-party policy and the native review API for every
platform in scope at execution time — not from model memory. Eligibility
comes from verified meaningful value in a stable product context. Apply the
same rule across sentiment, payer status, spend, tier, private feedback,
complaint history, and likely rating.

Money, rewards, access, remedies, support, referrals, warranties, appeals,
accounts, data rights, and product flow stay independent of review state. Use
the platform's native surface and neutral product wording. Help and private
feedback remain reachable in every request state.

Persist the policy revision, eligibility reason, value event, audience
decision, attempt time, native result when available, and cooldown.

Open [platform policy and request state](platform-policy-and-state.md) for
adapter fields, the request lifecycle, official policy sources, and acceptance
conditions.
