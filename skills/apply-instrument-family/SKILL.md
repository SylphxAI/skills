# Apply Instrument Family

Use when building, reviewing, releasing, or redesigning Sylphx local-first agent instruments (PDF/image/video/architecture/web/code evidence products).

## Load

1. Family law: `docs/knowledge/instruments/INSTRUMENT-FAMILY-LAW.md`
2. Envelope schema: `schemas/instrument-evidence-envelope.schema.json`
3. Product map: `references/product-map.md`

## Workflow

1. **Classify the product.** Instrument vs deliberation vs host/runtime vs retired.
2. **Name the brand identity.** Canonical npm/bin/MCP title must be brand, not transitional `*-reader-mcp`.
3. **Enforce architecture.** Core → SDK → CLI/MCP adapters. No dual production engines.
4. **Enforce tools.** Few primary tools; ops enums for follow-ups; no internal helpers in tools/list.
5. **Enforce envelope.** Every result carries envelope v1 fields (status, tool, product, route, payload, warnings, gaps, locators when applicable).
6. **Enforce composition.** Host/skills compose products. Do not revive Prism as a product MCP.
7. **Release honestly.** Registry + native + doctor + behavioral proof — not CI alone.

## Terminals

- Instrument: brand-sole install path, sole engine, envelope-conformant primary tools, local-first default.
- Retired (Prism/filesystem/mcp-server-sdk): explicit archive text; no install CTA as current authority.
- Consultant: separate deliberation category; do not claim Instruments local-evidence law.

## Non-goals

- Building a multi-product monorepo
- Hosted BaaS, billing, or tenancy inside instrument packages
- Generative vision as authority over locators
