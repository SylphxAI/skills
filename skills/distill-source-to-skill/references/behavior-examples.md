# Distill Source To Skill Behavior Examples

These examples record route intent and artifact oracles. They are not native
host activation evidence.

| Request | Expected behavior |
| --- | --- |
| “Turn these architecture docs and repository notes into one installable skill that preserves the actual decision method.” | Select this skill; name the source boundary, extract mechanism cards, choose one package shape, and validate a source-independent task. |
| “Rewrite the description and method in this one existing skill; its source is already understood.” | Use `author-skill` as the primary method. |
| “Review the whole skill repository for overlap, deleted knowledge, and retirement candidates.” | Use `curate-skill-repository`; portfolio ownership is the job. |
| “Summarize these meeting notes for me.” | Do not create a skill unless the user asks for a reusable package and a recurring job exists. |

## Artifact oracle

A valid Source-To-Skill Report names exact sources/revisions and unavailable
material; audience, sensitivity, license, and publication authority; root job,
accepted artifact, package shape, and semantic owner; mechanism-level keep,
merge, and discard decisions; positive and negative behavior examples; package
files and repository-native validation; source-independent task result; and
residual source limitations. Historical access never becomes publication
authority.
