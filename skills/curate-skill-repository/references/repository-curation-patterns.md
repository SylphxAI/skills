# Skill Repository Curation Patterns

## Four separate verdicts

Never compress these questions into one score or lifecycle label:

1. **Job value** — Is this a recurring or strategically material job whose
   mishandling loses product quality, revenue, trust, safety, or operating
   leverage?
2. **Package value** — Does the current package contain non-derivable decisions,
   state, checks, failure modes, or procedures, and can an agent execute it
   without hidden context?
3. **Route value** — Would a user intentionally request this job, and can its
   artifact be accepted independently from neighbouring skills?
4. **Evidence state** — Is the route only authored or sponsored, or does exact
   current routing, behavior, adoption, or authority evidence exist?

A valuable job may have a weak generated package; rebuild it instead of
publishing the shell or declaring the job worthless. A strong package may be a
reference module rather than a separate route. Presence is not adoption or
behavior proof.

## Complete corpus

Inventory current installable packages, active proposals, retirement records,
default-branch history, and closed-unmerged sources relevant to the requested
boundary. The owner is not the discovery index. Access to a private source or a
historical branch is not permission to publish it.

For each candidate inspect:

- concrete request and accepted artifact;
- `name` and `description` as the native discovery contract;
- unique decisions, procedures, states, failures, examples, helpers, and
  evaluation assertions;
- intended audience, sensitivity, license, and publication authority;
- canonical owner and nearest neighbouring routes; and
- authored, validated, candidate, landed, published, installed, and observed
  evidence as separate states.

## Collision decisions

Use job and artifact, not topic, as the merge test.

| Relationship | Decision |
| --- | --- |
| Same topic, different accepted artifacts | Keep both; clarify triggers and handoff |
| Same job and artifact, one package strictly stronger | Absorb into the clearer owner |
| Shared sub-method only | Keep routes; place the method under one reference owner |
| Broad orchestrator and narrow specialist | Keep only if the orchestrator owns a distinct composition artifact |
| Generic advice with no knowledge delta | Archive the implementation without inventing a replacement |
| Plausible route with unknown demand or method | Investigate; do not publish a shell |

Before absorption, map every unique decision rule, state machine, failure mode,
example, helper, and oracle to its destination. A destination path or file hash
is not proof the mechanism survived.

## Dispositions

| Finding | Disposition |
| --- | --- |
| Strong independent job, artifact, package, and boundary | Keep or publish as an honestly labelled candidate |
| Valuable job, weak or generated current bytes | Rewrite |
| Valuable mechanisms, same accepted artifact as a stronger owner | Absorb with mechanism-level mapping |
| Valuable capability owned by another canonical project | Transfer and verify coverage |
| Plausible value or unresolved collision | Investigate with a resolving source or forward test |
| No non-derivable procedure after semantic inspection | Archive implementation |

Missing usage, owner attention, or benchmark proof is not positive evidence
that a package is generic.

## False-negative review

Review hidden, rejected, or historical material against the proposed target
without relying on the preferred disposition. Ask what useful capability,
owner knowledge, distinct artifact, failure mode, or route would be lost. Use a
separate context only when repository authority permits it; otherwise perform a
fresh local pass over the raw material before reading the proposed verdict.

Resolve material disagreement through deeper source inspection or realistic
forward tests. If neither is available, keep the uncertainty visible as a
rewrite or investigation.

## Native discovery

The portable discovery surface is `name` plus `description`. Test realistic
positive, nearby-negative, compound, abstention, multilingual, ambiguous,
correction, and misleading-keyword requests under the supported host's actual
listing and truncation behavior. A correct body cannot repair metadata that did
not route. A static prompt table records intent but does not prove native host
selection.

## Curation record

For every material route record:

- recurring request and accepted artifact;
- four verdicts and evidence state;
- unique mechanisms and nearest neighbours;
- canonical owner and disposition;
- exact content action and absorption map when applicable;
- false-negative result and unresolved disagreement; and
- structural, behavior, candidate, landed, published, and installed states
  without collapsing them.
