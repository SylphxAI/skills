# Curate Skill Repository Behavior Examples

These examples record route intent and artifact oracles. They do not prove
selection by a native host.

| Request | Expected behavior |
| --- | --- |
| “Audit this skills repository, including deleted packages and closed proposals; recover unique methods and resolve route collisions.” | Select this skill and reconstruct the corpus before deciding dispositions. |
| “Create one new skill from these supplied notes.” | Use `distill-source-to-skill`; a portfolio verdict is unnecessary. |
| “Improve the description and procedure of this one known package.” | Use `author-skill` unless repository-wide ownership or collision evidence appears. |
| “Delete every package with no usage counter.” | Reject the premise; missing adoption evidence does not prove job, package, or route value is absent. |
| “幫我睇晒 current、history 同 closed PR，唔好執漏有用 skill，但唔好復活舊 control plane。” | Select this skill; separate current authority, historical mechanisms, and rejected infrastructure. |

## Artifact oracle

A valid curation report includes the repository and publication boundary,
complete relevant corpus, separate job/package/route/evidence verdicts,
canonical owner and exact disposition for each material capability,
mechanism-level absorption maps, false-negative review, missing or weak
capabilities, resolving evidence for disagreements, repository-native
validation, and distinct content/candidate/landed/published/installed states.
