# Curate Skill Repository

Make the repository easier for native skill discovery and more useful on real recurring jobs.

## Method

1. Establish the repository boundary, intended users, supported Agent Skills format, publication scope, and current canonical branch.
2. Enumerate every skill package and inspect its `name`, `description`, procedure, references, scripts, assets, and nearby neighbours.
3. Identify the recurring request, independently useful outcome, specialized method, and acceptance boundary for each skill.
4. Compare neighbouring skills by job and outcome rather than topic words or folder shape.
5. Keep distinct packages for independently requested and independently accepted jobs.
6. Merge packages that share one job, outcome, and acceptance boundary. Map unique instructions and resources to their destination before moving them.
7. Split a package when a contained job is routinely requested and accepted on its own.
8. Retire a route after its unique useful knowledge has a clear canonical home.
9. Rewrite descriptions in natural language so native discovery can distinguish intended requests from nearby jobs.
10. Validate the resulting packages against the Agent Skills specification, resolve local links, run included scripts, and exercise important routes with representative prompts.

## Review questions

- What real request should select this skill?
- What result can a user independently accept?
- What procedure or domain knowledge improves that result?
- Which package owns the same job or the nearest adjacent job?
- Where will each unique instruction, example, script, or reference live after the change?
- Does the final package remain concise at discovery time and useful after loading?

## Output

Return the portfolio decisions, exact package changes, knowledge moves, representative validation performed, and any capability whose owner remains genuinely unclear.
