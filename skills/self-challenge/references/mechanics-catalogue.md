# Mechanics catalogue

Trigger: designing a product, a feature, an offer, or a return loop.

The menu behind [mechanics](mechanics.md). Each row describes a candidate design,
not a current vendor deployment or a promised lift.

## How to use it

Review sections relevant to the decision. State the target outcome, choose
mechanisms that fit, and record material alternatives. The example durations,
counts and schedules illustrate a design; size them for the product's actual
journey and economics. Apply the product's policy and current market/store rules
through [mechanics](mechanics.md#hard-lines).

**Fits:** `G` game, `A` consumer app, `S` SaaS or B2B, `E` education,
`W` website, marketplace or commerce. Tags suggest where to consider a mechanism;
`all` spans those categories.

## Evaluating evidence

Judge education by learning as well as activity. For any published result, read
the study's actual population, outcome, design, date and uncertainty before
transporting it to another product. A vendor experiment can be informative;
source incentives and transferability still matter.

Use the [contribution model](commercial.md#pricing-mechanism-design-and-unit-economics)
and a decision-relevant experiment to choose the offer. Verify the current rules
for the selected market and storefront ([legal surface](commercial.md#legal-surface)).
