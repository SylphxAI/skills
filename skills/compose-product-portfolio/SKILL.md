# Compose Product Portfolio

Organize products around independently useful customer jobs and explicit semantic ownership.

## Method

1. Define the portfolio objective, customers, recurring jobs, existing products, proposed capabilities, shared dependencies, channels, and commercial constraints.
2. Classify each candidate as a standalone product, embedded capability, shared substrate, connector, composed experience, or bundle.
3. Compare independent customer value, semantic ownership, state authority, onboarding, lifecycle, support, release, failure, entitlement, and operational cost.
4. Keep a capability embedded when its value and lifecycle naturally belong to one product.
5. Create a product unit when it has a coherent promise, independently adoptable entry point, owned state, supported public contract, lifecycle, and operating owner.
6. Define each connector as a thin adapter over one owned public contract with explicit authentication, authorization, tenancy, versioning, idempotency, quotas, failure, reconciliation, privacy, and replacement behavior.
7. Keep shared identity, billing, catalog, discovery, and UI surfaces separate from product-domain truth.
8. Let internal use exercise the same supported semantic contract and lifecycle available to external consumers.
9. Define bundle composition, entitlements, support routing, data boundaries, exit, migration, and retirement.
10. Validate representative standalone and composed customer journeys.

Read [Composable product portfolio method](references/composable-product-portfolio-method.md) for detailed boundary tests and connector design.

## Output

Return the product-unit map, capability ownership, connector graph, shared substrates, composed experiences, bundles, operational responsibilities, and keep, extract, merge, replace, or retire decisions.
