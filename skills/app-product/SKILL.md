# App Product

Design an application whose promise is getting a recurring job done — not play and not a multi-tenant SaaS platform. A setup, identity, or payment wall before visible value is not first value.

- Fast first value without asking for setup, identity, or payment before the value is visible.
- Durable value through saved work, continuity, and user-controlled personalization — with export, deletion, and exit.
- Platform behavior for each selected web, mobile, or desktop target: input, permissions, offline, updates, uninstall.
- A dormant extension does zero startup, SDK, permission, or network work.

Open only the files the current app needs: [thesis and experience](references/app-thesis-and-experience.md), [system portfolio](references/app-system-portfolio.md), [quality and reach](references/app-quality-and-reach.md), [desktop OS](references/desktop-os-experience.md), or [validation](references/app-validation-and-automation.md).

Use `saas-platform` for public-to-authenticated multi-tenant service. Use `game-product` when the promise is play. Use `prototype-product` when the next need is a discriminating probe, not a product thesis.
