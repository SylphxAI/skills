# App Validation and Automation

Use validation to answer the product question at hand. State whether an input
is supplied, observed, assumed, hypothesized, or decided, and keep design,
implemented behavior, released identity, and observed live behavior distinct.

## Product measures

Choose measures that represent the selected product promise and support a real
decision. Common branches include:

| Area | Useful signals | Counter-signals |
| --- | --- | --- |
| Message and acquisition | expectation comprehension, qualified visit or install | mismatch, bounce, uninstall |
| First value | useful result, saved continuity, successful setup | denial, error, abandonment, support need |
| Core value | outcome completion, quality, saved effort, repeat depth | rework, undo, accessibility exclusion |
| Retention | return by natural cadence and reason | fatigue, unhealthy use, notification dependence |
| Collaboration | reciprocal use and recipient value | spam, reports, privacy incidents |
| Commercial value | purchase, fulfillment, retained value | refund, chargeback, regret, support cost |
| Quality | startup, input, sync, offline, recovery | data loss, battery, thermal, low-end failure |
| Trust | consent, export, deletion, support resolution, appeal | complaints, opt-out, reversed enforcement |

Use only the branches created by selected capabilities. Give each metric a
purpose, source, definition, population, time window, consent behavior, owner,
freshness expectation, and response action. A product dashboard earns its cost
when it changes a decision or operating action.

## Product decisions

Select actions within current legal, platform, safety, child, consent, privacy,
rights, and authorization boundaries. Compare expected durable user value,
commercial value, option value, runtime cost, user attention, support cost, and
recoverable downside. Route ambiguity to its authority owner with an expiry and
safe interim behavior.

## Implementation handoff

For each selected capability, provide:

- its user value, complete target behavior, state owner, and interfaces;
- the shared primitive or implementation owner and dependency order;
- migration, dormant behavior, degradation, recovery, and user communication;
- acceptance conditions and the smallest end-to-end checks that exercise them;
- accessibility, localization, privacy, security, performance, and failure
  checks that apply to the changed path.

Specialists consume the current blueprint and record implementation and release
state in the product repository. The blueprint links to those owners instead of
copying their live facts.

## Learning and automation

Combine feedback, support, reviews, product behavior, quality, commercial, and
safety signals with consent-aware collection and privacy controls. Group related
signals, form a falsifiable cause hypothesis, reproduce or simulate it, test a
bounded change, and read the affected product result. Keep or recover the change
from that result.

Automation may collect, deduplicate, route, and apply reversible changes within
declared authority. Consent, entitlement, spend, enforcement, public claims, and
irreversible effects stay with their owning controls. Qualitative work explains
mechanisms, representative measurement estimates prevalence, and controlled
experiments estimate causal effects where feasible.

## Availability and release truth

Selected capabilities are available through semantic permission, role,
entitlement, consent, age, territory, platform, service-health, and dependency
conditions. A preserved extension point stays dormant. Record the actual test,
release, or live observation supporting each claim and run the path changed by
the candidate.

## Blueprint contents

A useful blueprint connects:

- target users, job, promise, objects, workflows, first value, recurring value,
  durable ownership, errors, and recovery;
- selected capabilities, their reasons, owners, shared primitives, dependencies,
  availability, migration, and handoffs;
- supported platforms, inputs, offline behavior, accessibility, localization,
  privacy, security, age modes, commerce, social behavior, and low-end quality;
- product measures, counter-signals, learning method, acceptance conditions,
  and unresolved questions.

Retrieve current official platform, storefront, territory, audience, and policy
sources when they govern a selected behavior. Record the source and retrieval
date in the product repository where the decision is made.
