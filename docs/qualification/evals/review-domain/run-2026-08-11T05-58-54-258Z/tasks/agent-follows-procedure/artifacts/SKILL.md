# Review Domain

When the primary outcome is an **assessment / review record** for a product or ops domain, run one review cycle.

This is **one user job** (review/assess). Domain checklists differ; they are references, not separate listing skills.

## When to use

- Go/no-go, risk, ops, growth, marketplace, privacy, security, game systems, etc. assessment
- Not for implementing the fix (use build/maintain skills) unless the user expands scope

## Method

1. **Frame** subject, surfaces, users, success criteria for the assessment, non-goals.
2. Open [references/review-playbook-skeleton.md](references/review-playbook-skeleton.md) for shared rhythm.
3. Open **one** domain pack from [references/INDEX.md](references/INDEX.md) (e.g. `launch-readiness`, `privacy-and-data-rights`, `game-economy`).
4. Gather evidence; separate fact / inference / unknown.
5. Produce **one** ranked findings + actions record for that domain.
6. For multi-domain synthesis after several reviews, open [references/multi-review-synthesis/METHOD.md](references/multi-review-synthesis/METHOD.md).


## Progressive disclosure

1. Open [references/INDEX.md](references/INDEX.md) and pick **one** domain pack matching the review ask.
2. Open only that pack's METHOD (and nested refs if the pack says so).
3. Optional multi-domain synthesis only when the ask requires it.

## Output

Domain review record · severity-ranked findings · residuals · recommended actions
