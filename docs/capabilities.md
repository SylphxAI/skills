# Skills capability graph

The destination is [vision.md](vision.md). This graph records durable product
responsibilities, not package counts, work queues, or publication claims.

| ID | Capability | Depends on | Done when |
| --- | --- | --- | --- |
| SKL-ROUTE | Discover the right requestable job | — | A supported host can select one semantic owner from concise `name` and `description` metadata for realistic positive, nearby-negative, compound, ambiguous, and multilingual requests. |
| SKL-EXECUTE | Execute a reusable method | SKL-ROUTE | The selected package gives an agent enough decisions, procedure, boundaries, output contract, and validation signals to complete its independently accepted job without chat memory or hidden company context. |
| SKL-COMPOSE | Apply reusable standards while doing a job | SKL-EXECUTE | Every authorized reusable company mechanism has exactly one job-shaped method or directly linked reference owner; owner-only, product-only, superseded, sensitive, and unknown material is explicitly excluded rather than copied into a second body of company law. |
| SKL-DISTILL | Distill authorized source into methods | SKL-EXECUTE | A multi-file or multilingual source corpus can be reduced to mechanism cards, an evidence boundary, one package shape, routing examples, and an installable candidate without republishing private or volatile facts. |
| SKL-CURATE | Recover and curate the method portfolio | SKL-ROUTE, SKL-DISTILL | Current packages, active proposals, retirement records, default-branch history, and closed-unmerged work can be classified and repaired without losing unique mechanisms, duplicating semantic owners, or treating historical presence as publication authority. |
| SKL-EVALUATE | Test method behavior and repository integrity | SKL-EXECUTE | Material routes are checked for useful behavior, false positives, false negatives, and accepted artifact shape, while structural and link checks reject only real package defects. |
| SKL-DISTRIBUTE | Publish portable packages through repository-native delivery | SKL-EVALUATE | Validated source can be reviewed, released, installed, and attributed through the supported repository and host paths with source, candidate, landed, published, and installed states kept distinct. |

Dependency edges exist only where the downstream capability cannot be correct
without the upstream contract. Individual job packages may be developed in
parallel when their semantic ownership and write sets do not collide.
